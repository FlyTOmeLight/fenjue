# 历史完整任务质量结果

2026-10-12 的实验比较冻结旧版 v3、新版 v5 与固定 Sol high：四个新合成任务，每组重复两次，共 24 次正式运行。任务覆盖诊断→修复→总结、文件整理、长工具证据后的参数提取，以及指代澄清后实施。

合格交付要求预算内完成、程序验收通过、独立 Codex Judge 全部标准通过。Judge 使用 gpt-6-astra/high，匿名查看需求、回答及验收证据；unknown 保留为未认证，不当作已发现错误。

| 策略 | 程序验收 | Judge pass / fail / unknown | 耗时秒 | 执行 token | 分类 token |
| --- | --- | --- | ---: | ---: | ---: |
| old-v3 | 8/8 | 8 / 0 / 0 | 474.0 | 1,305,120 | 68,919 |
| new-v5 | 8/8 | 6 / 1 / 1 | 531.1 | 1,377,121 | 73,870 |
| fixed-sol-high | 8/8 | 7 / 1 / 0 | 503.7 | 1,172,134 | 0 |

新版执行 token 增加 5.5%，耗时增加 12.0%。缓存输入比例不同，token 不能直接换算费用；Judge 开销也未纳入执行 token。该结果未显示新版的质量或效率收益。

两个 fail 来自备份方案说明擅自将“每天增量”改成“其余六天增量”；最终 JSON 参数正确。错误分别出现在新版的 Astra high 回答和固定 Sol high 回答中，不能归因于阶段降档。

新版的 unknown 来自独立验收回执过于简略：实际检查了索引、并发、非法输入和异常传播，但回执只显示任务 id 与 passed，Judge 无法确认检查范围。保留原 unknown，未通过重复判分取得 pass。

## 方法与证据边界

- Codex CLI 0.162.1；每次预算 180 秒、30 个工具开始和 250,000 个可观测累计 token。token 为软上限。
- 模型工作区与外部验收隔离，工具网络关闭；权限探针确认不能读取外部验收文件。
- 先校准两个 Judge 样例，再判分 24 份产物，共 26 次 Judge 调用。
- 初始频率文字验收误拒绝任务允许的“全量/增量”后缀。统一修正后重查全部产物；原验收 21/24，修正验收 24/24。这不是完全按原预登记验收完成的实验。
- 两次前期无效启动绕过路由，停止后排除在 24 次正式指标之外；仍消耗了模型用量。
- 四个合成任务各重复两次，不证明日常质量等价，也没有人工偏好一致性验证。
- 对照是完整冻结版本，不能将差异全部归因于单个策略修改。

本页是维护者历史实验的公开摘要。原始日志、冻结版本与私有运行脚本留在本地，不随仓库发布，读者无法仅凭本仓库独立复现这批历史指标。

可公开重跑的六任务套件是另一组用例，见 [任务评测](task-evaluation.md)；不能把它的输出称为本页四任务实验的复现。后续新比较应在执行前公开固定任务、版本、配置与验收标准，并提供不含私有材料的证据。
